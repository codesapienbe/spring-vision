What the token stores, and who can call what

Reflects the current state of keycloak/realm-spring-vision.json, KeycloakRealmRoleConverter, and the requireAdminRole() gates in VisionTool.java — verified against the actual code, not the plan. Regenerate this page by hand whenever those files change; nothing wires it up automatically.

1. What's actually in the access token

Keycloak issues a standard JWT via the client_credentials grant (no human user or password involved — the caller is a service account tied to a client). A real token carries far more than realm_access.roles, but the app only reads one claim:

ClaimExample valueRead by the app?
isshttp://localhost:8180/realms/spring-vision✓ validated — must match issuer-uri
exp / iatUnix timestamps✓ validated — Spring rejects expired tokens automatically
Signature (JWKS)RS256 over the header+payload✓ validated — fetched from Keycloak's JWKS endpoint
realm_access.roles["mcp-user","mcp-admin"]✓ this is the only claim RBAC decisions are based on
subservice-account-spring-vision-mcp-desktopnot used
azp / clientIdspring-vision-mcp-desktopnot used
scopeemail profilenot used — this is what Spring Security's default converter reads; we replaced it because Keycloak roles live elsewhere
resource_access.*.roles(client roles, unused)not used — only realm roles are assigned in the realm export
aud—not checked — no audience restriction configured
Practical effect: anything with a validly-signed, non-expired token from this realm is "authenticated." Whether it can call a specific tool comes down entirely to whether realm_access.roles contains mcp-admin — checked by a manual SecurityContextHolder read in VisionTool.requireAdminRole(), not by Spring's declarative @PreAuthorize (unreliable on @Tool methods in current Spring AI — see the code comment referencing spring-projects/spring-ai#2356).

Design intent: mobile deliberately does not get mcp-admin. Its token lives 24× longer than desktop's, so if it ever leaked, the blast radius is capped to general-purpose tools only — biometric enrollment, threat detection, and PII-document recognition stay off it.
